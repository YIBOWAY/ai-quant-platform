# 前端使用问题说明与本次改进

这份说明回答几个实际使用中遇到的问题，也记录本次已经做的改进。

## 1. 期权雷达为什么点了“运行今日扫描”很久没反应？

期权雷达跑的是只读期权链扫描。使用 Futu 数据时，它会按标的逐个拉期权链、报价、IV 等数据；如果扫描范围比较大，就会受到 OpenD 和行情接口节奏限制，所以等待时间会比较长。

本次改进：

- 点击“运行今日扫描”后，右侧会显示“正在扫描”和已等待时间。
- 扫描完成后，页面会主动读取刚保存的今日快照。
- 如果扫描失败，会在页面上显示错误，不再让用户只看到旧表格。

使用建议：

- 想快速验证流程，先把 Top N 调小。
- 真正做全市场雷达，建议用命令或定时任务提前跑，前端主要查看结果。

## 2. 因子实验室输入 NVDA 后，信号评分和 IC 为什么是 0？

当前因子实验室不是单只股票打分器，它更像“在一组股票里比较谁更强”。信号评分和 IC 都需要多个标的放在一起比较。

如果只输入 NVDA：

- 因子值本身可以算出来。
- 但没有其他股票可比较，评分会很容易变成 0。
- IC 和分位收益也缺少足够样本，结果会空或没有意义。

本次改进：

- 表单会提示需要输入一组可比较标的。
- 单标的运行后，结果详情页会显示说明，不再只留一堆 0 让人猜。
- 运行完成后会直接进入本次结果详情页。

建议输入类似：

```text
NVDA,AAPL,MSFT,AMD,QQQ,SPY
```

## 3. 如果想新增因子，应该怎么做？

新增因子仍然需要在后端写因子逻辑，因为因子是研究计算的一部分，不适合只在前端临时拼出来。这个平台面向开发者维护研究逻辑，不是面向前端用户自由输入表达式造因子。

但本次已经做了一个改进：默认因子运行会从因子注册表生成，后续新增因子不需要再维护两份清单。

新增流程：

1. 写一个新的因子类，继承现有因子基类。
2. 在因子注册表里登记这个因子。
3. 后端的因子列表、因子运行、回测默认因子会沿用注册表。
4. 如果实验配置里也要用这个因子，在实验配置中写入它的 factor_id。

也就是说：后端要新增能力，前端通过已有接口使用它；不是每次都重新写一套前端逻辑，也不需要做前端表达式编辑器。

## 4. 回测器运行 META 后为什么还是 0？

这和因子实验室类似。当前回测器使用的是“在一组标的中排序，买入分数靠前且为正的标的”的研究策略。

如果只输入 META：

- 没有可比较对象。
- 分数可能全是 0。
- 策略不会买入，交易数为 0。
- 总收益、夏普、回撤自然都显示 0 或接近 0。

本次改进：

- 单标的回测会显示说明。
- 如果没有生成模拟交易，详情页会明确说明原因。
- 运行完成后会直接进入本次回测详情页。

建议输入类似：

```text
META,AAPL,MSFT,GOOGL,QQQ,SPY
```

## 5. Backtest Run Detail 里的 backtest-xxxx 是哪里来的？

这是后端本地回测框架生成的运行编号，不是外部系统。

每次调用回测接口，后端会：

- 生成一个 backtest 开头的运行编号。
- 保存本次请求、指标、权益曲线、订单、持仓和成交记录。
- 前端再读取这个编号对应的结果详情。

所以它确实来自你项目后端，只是之前单标的输入没有产生交易，看起来像“框架没真正用起来”。

## 6. 策略复现后续怎么新增策略？

现在的“策略复现”页面复现的是一个具体论文策略，不是通用策略商店。

更靠谱的做法是：

- 每个新论文或新策略先在后端形成独立、可测试的研究模块。
- 后端提供一个清楚的运行接口。
- 前端从后端读取可运行策略清单，再按策略类型展示参数表单。

目前新增一个完整复现策略，仍需要后端先写逻辑，再接到前端。但长期更好的方向是做“策略/复现注册表”，让前端根据注册表自动展示可运行项，而不是每新增一个策略就手写一整页。

## 7. 实验管理在哪里运行实验？

之前实验管理页主要是查看本地实验结果，入口不明显。

本次改进：

- 实验管理左侧新增“运行实验”表单。
- 提交后会调用后端实验运行接口。
- 运行完成后会刷新列表，并展示最新实验结果。

当前实验运行可选择 `sample`、`futu` 或 `tiingo` 数据源；`sample` 适合验证参数扫描和结果管理流程，真实研究应直接选择真实 provider。`agent_summary.data.source` 会记录实际数据源，“发送至回测”会把参数和同一数据源一起带到回测器。

## 8. 顶部“中文”为什么会竖着？

这是顶部栏空间挤压导致的换行问题，不是中文内容本身坏了。

本次改进：

- 语言切换按钮固定为横向显示。
- 顶部右侧工具区不再被导航挤压成窄列。

## 本次补充

这几个现象的共同问题不是后端完全没写，而是前端没有把“当前模型需要什么输入”“正在运行什么”“为什么没有交易或评分”讲清楚。

本次改动的重点是让页面更像可用工具：

- 运行后明确显示进度或进入结果详情。
- 输入不适合时直接提示原因。
- 结果为 0 时给出解释。
- 实验管理补上可见的运行入口。
- 语言按钮修成横向显示。

所有这些输出仍然是研究用途，不是投资建议，也不会下单。

## 9. 为什么回测和 Factor Lab 都偏向多标的？

当前这条股票研究链默认不是“分析一只股票自己该不该买”，而是“在一组标的里比较谁更强”。

Factor Lab 属于 Phase 2。它的主要作用是检查一个因子能不能把一组股票排出有意义的高低。比如同一天里，动量、波动、流动性、RSI、MACD 这些因子对 SPY、QQQ、AAPL、MSFT 等标的分别打分，再观察高分组后续是否真的表现更好。

回测器属于 Phase 3。它读取 Phase 2 生成的分数，然后使用当前的默认研究策略：每天买入排名靠前、而且分数为正的标的。

所以它们都需要一组标的，不是因为系统不能跑单只股票，而是因为当前默认逻辑就是横向比较。单只股票可以生成价格和部分因子值，但没有比较对象时，评分、IC、分组收益、买入选择都会变得很弱，甚至直接显示 0。

两个标的只是最低门槛，不是理想样本。SPY 和 QQQ 可以用来验证流程，但不适合得出强结论。更合理的输入应该是一组同类标的，比如大科技、行业 ETF、半导体股票池，或者你真正想比较的一篮子候选。

## 10. SPY、QQQ 的 Factor Lab 结果说明什么？

SPY、QQQ 这次结果说明：系统确实算出了因子值，也生成了评分、IC 和分组收益，但样本太少，结论很有限。

如果只有两个标的，IC 很容易在 1 和 -1 之间跳动，看起来数字很“满”，但稳定性很差。分组收益如果差异很小，就说明在这段时间、这组标的、这些默认因子下，没有看到很强的区分能力。

Factor Lab 的价值不是直接告诉你“买哪个”，而是先筛信号：

- 哪些因子可能真的能区分强弱。
- 哪些因子只是噪声。
- 哪些因子需要更长时间、更大股票池或不同市场环境再验证。

真正要进入交易，还需要继续经过回测、实验管理、风控和模拟交易。不能把 Factor Lab 的表格直接当交易指令。

## 11. 回测基准为什么默认是 SPY？

回测器现在默认使用 `SPY` 作为基准，不再拿输入列表里的第一个标的当基准。

所以如果你输入的是 `META,AAPL,MSFT,GOOGL,QQQ,SPY`，页面默认仍会用 SPY 做大盘对照。你也可以在回测配置里手动填写其他基准。

这个改动是为了避免把研究篮子里的第一个股票误当作市场基准。后续仍可以继续补充：

- 增加“输入标的等权持有”作为组合基准。

因此，如果你在旧运行记录里看到 META 之类的标的作为 benchmark，那通常是旧结果的历史配置；新运行默认应显示 SPY，除非你手动改了基准。

## 12. 为什么回测页没有行业上限输入？

行业上限只有在系统知道每个标的属于哪个行业时才有意义。只填一个“行业上限”数字，但没有行业映射，会让人误以为系统已经限制了整个行业仓位。

所以现在的处理是：

- 前端回测器只展示单标的上限。
- 后端仍保留 `sector_cap` + `sector_map` 能力，方便开发者或脚本调用。
- 如果 API 请求只传 `sector_cap`、不传 `sector_map`，后端会拒绝。

这和新增因子的原则一致：更复杂的研究约束放在后台代码和明确数据结构里，不在前端放一个容易误解的输入框。

## 13. 期权雷达里的财报 Yes / No 是什么标准？

期权雷达里的财报 Yes / No 不是只看“今天是否发财报”。

当前标准是：如果这个标的的下一次已知财报日期在扫描日之后的 7 天内，就显示 Yes。当天发财报也算 Yes，未来几天内发财报也算 Yes。

它的作用是风险提醒。卖期权时，财报附近可能出现跳空、隐含波动变化和流动性变化，所以系统会把这类候选扣分。

但只显示 Yes / No 信息量确实不够。后续更好的显示方式应该包括：

- 具体财报日期。
- 距离财报还有几天。
- 数据是否新鲜。
- 如果数据源支持，再区分盘前或盘后。

目前后端已经保存了财报日期，前端还没有把这部分信息展示充分。这个字段现在可以作为风险提示，但还不适合作为完整的财报决策依据。
