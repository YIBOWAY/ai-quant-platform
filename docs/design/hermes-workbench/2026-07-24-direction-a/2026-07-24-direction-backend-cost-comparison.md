# 三方向后端配合量与代价对比（2026-07-24）

基于 `2026-07-24-demo-data-contracts.md` 的字段级合同校准。
**总结论：A / B / C 三个方向均不需要任何新后端接口、schema 变更或 migration。**
所有数据来自现有 5 个 GET + workspace 脊柱（均已在 L/V 系列验收）。代价差别在
前端工程量、字段展示面、断点适配与 QA 范围。

---

## 方向 A · COO 概览派

**后端必需改动：0 项。**

后端"配合"全部是复用确认（不改代码，验收时核实即可）：

1. Today 页新增消费 `GET /api/hermes/gateway`（已存在、GET-only 允许列表内）→ 状态条"Hermes 在线"。
2. "待我处理"里命令审批的 允许一次/拒绝 走已交付的 V7a decide（`allow_once|deny` CAS）；按钮在 mutation flag 关闭时不出现（现有规约不变）。
3. workspace snapshot 的 owner-session/bootstrap 流程在 Today 页复用（L2a 起已交付，chat 面板在用同一条）。
4. Gate 2"去评审"链接到现有 `/hermes/approvals` 页，无新写路径。

可选优化（不做也能上线）：
- Today 并行 GET 从 3 → 4（加 gateway）。若将来想合并为单一聚合 endpoint（如 `GET /api/hermes/today`），那是纯性能优化，不是前提。
- chat off 时状态条若要显示 `command_ledger` 健康，需要 Today 页也消费 snapshot；不接受的话降级为只显示 3 项即可。

## 方向 B · 交易台密度派

**后端必需改动：0 项（同 A 的全部复用确认）。**

但要注意两点（不是后端改动，是展示规约）：

- B 的"系统健康 Authority"表展示 `authority_health` 的 `hermes_gateway="dark"`、`mutation` 等内部状态——这些字段后端已产出（前端 Today 目前未消费），展示时需要文案纪律，不能把 dark/off 渲染成故障。
- B 的"数据源 Sources"表直接渲染 artifacts envelope 的 `sources[].status` 四态——normalize/fail-closed 映射必须沿用现有层。

B 的真实成本在前端：全新表格组件族、tabular-nums 对齐、每格状态枚举渲染、密表在 1280/768/390 的回流策略、以及最大的视觉回归面。

## 方向 C · 编辑叙事派

**后端必需改动：0 项（同 A）。**

唯一的潜在后端增项（建议 V1 不做）：

- 若"今日摘要"lede 段落要由 **Hermes 生成**（每日叙事文本），则需要新能力：定时生成 + 存储 + freshness 标记 + 失败降级。这是三个方向中唯一可能的后端加项。
- **推荐做法：前端模板派生**（"系统正常 · 晨报 07:30 已发布 · 有 N 件事等你处理"，由 attention 计数 + artifacts `occurred_at` 拼装），零后端成本；生成式摘要留作后续独立 slice 评估。

## 代价对比

| 维度 | A · 概览 | B · 密度 | C · 叙事 |
|---|---|---|---|
| 后端新接口/schema/migration | 0 | 0 | 0（模板摘要）；若生成式摘要则 3 方向中最高 |
| 与现有前端代码复用度 | **最高**（在现有 Today/viewModel 上重构） | 最低（全新表格组件族） | 中（新表现层，但组件简单） |
| 字段展示面 | 中 | **最大**（authority/sources/session 全量） | 最小 |
| 断点适配难度（1440/1280/768/390） | 中 | **最大**（密表回流） | **最小**（单栏阅读流） |
| 视觉回归 / QA 面 | 中 | **最大** | 小 |
| 诚实性红线风险 | 低 | 中（内部 dark 状态的展示纪律） | 低 |
| 交互面（按钮/决定/链接） | 中（复用 V7a） | 中 | 小 |
| **综合代价** | **最小** | **最大** | 小（与 A 接近；但偏离现有组件库更远） |

## 结论与建议

- **代价最小：A**——复用最多、风险最低、正好也是你满意的方向；C 紧随其后。
- **代价最大：B**——不是后端贵（也是 0），而是前端表格族 + 断点 + QA 面最贵；且与用户此前"保留 full-width trading desk 密度"的诉求部分重叠，可作为后续增强而非首发。
- **建议路径**：按 A 落地首发；把 B 的"自动化 4-job 矩阵"和"Authority 健康表"作为后续可插拔模块借入 A 的"系统状态"抽屉；把 C 保留为 `/brief` 晨报阅读体验或"阅读模式"的候选方向，不浪费。
